# Short benchmark 模型能力评价维度

本文档只固定能力维度，不固定 criterion 映射、统一抽取脚本、总分权重或现有榜单关系。后续评价每个模型时，可根据该模型的实现方式、执行轨迹、失败模式和产物特点微调证据抽取项，但不得改变八个维度的定义边界。

## 1. 指令遵循（Instruction Compliance）

衡量模型是否准确执行显式任务约束，包括允许修改范围、禁止行为、指定工具或命令、公开 API、输出格式、确认文件、测试方式和最终交付状态。

评价时需要区分：

- 对任务要求理解错误；
- 明确要求被遗漏；
- 使用了被禁止或不合适的工具；
- 修改或生成了范围外文件；
- 输出格式或公开接口不符合要求；
- 声明内容与实际产物不一致；
- 完成代码后没有进行必要的交付检查。

## 2. 核心业务语义（Core Business Semantics）

衡量模型是否正确理解并实现任务的主要业务目标，而不只是让公开 smoke 通过。

关注内容包括：

- 输入经过处理后是否得到业务上正确的返回结果；
- 状态变化是否符合任务定义；
- 合并、删除、依赖、淘汰、过期和规范化等核心规则是否正确；
- 异常路径是否符合业务语义；
- 是否存在只针对样例通过、但没有真正实现规则的情况。

## 3. 类型与边界精度（Type & Boundary Precision）

衡量模型处理严格类型、特殊类型和边界场景的精确程度，重点识别“主体逻辑正确，但边界处理不够严格”的实现。

关注内容包括：

- `bool` 与 `int` 等特殊继承关系；
- plain type 与 subclass；
- 等值与对象同一性；
- 空值、零值、负值和非法类型；
- 上下界及精确时间边界；
- NaN、无穷值和极端数值；
- 语法错误、重复字段、乱序输入和非法单位；
- 错误发生位置及错误类别的精确性。

## 4. 数据完整性与生命周期（Data Integrity & Lifecycle）

衡量实现是否保护输入、结果和内部状态，避免数据污染、残留引用和生命周期错误。

关注内容包括：

- 调用前后输入是否保持不变；
- 结果是否与输入中的可变容器完全隔离；
- 是否存在浅复制或隐藏别名；
- 替换、删除、过期和淘汰后旧对象是否被彻底释放；
- 是否保留 stale object、tombstone 或无用历史结构；
- 内部状态在连续操作后是否仍然一致；
- 资源释放是否及时且完整。

## 5. 确定性与协议纪律（Determinism & Protocol Discipline）

衡量相同输入是否稳定产生相同结果，以及实现是否严格遵循公开接口和数据协议。该维度不评价速度，只评价行为的可预测性和稳定性。

关注内容包括：

- 输出顺序是否稳定；
- 保留项和新增项的位置是否符合协议；
- 是否严格遵守一次性 iterable 的消费次数；
- 分层、依赖和循环节点顺序是否确定；
- 返回值类型和结构是否稳定；
- 异常类型、错误码、错误属性和错误位置是否稳定；
- 多次调用或重放是否得到一致结果；
- 是否依赖 set、hash 或遍历顺序的偶然行为。

## 6. 可扩展性与性能（Scalability & Performance）

衡量实现面对深层、长链、大规模或高频输入时，是否仍能在合理资源预算内正确完成。

关注内容包括：

- 算法时间复杂度和空间复杂度；
- 深层输入是否触发递归上限；
- 大规模输入是否超时；
- 是否存在随输入增长而失控的内存结构；
- 批量清理、过期扫描和图遍历的效率；
- 是否存在不必要的重复遍历、全量复制或排序；
- 规模扩大后业务结果是否仍然正确；
- 性能优化是否破坏边界正确性。

## 7. 泛化能力（Generalization）

衡量模型能否把公开规则正确推广到未直接展示、但可以从契约推出的新组合和新输入形态。

关注内容包括：

- 更深的嵌套结构；
- 容器内部组合和混合对象；
- 更大数值和更长输入；
- 不同但等值的对象；
- 多个规则同时出现的组合场景；
- 公开样例没有覆盖的合法输入；
- 是否存在硬编码样例、固定阈值或特殊分支；
- 新输入形态下是否仍保持原有契约。

## 8. Token 效率（Token Efficiency）

衡量模型为获得对应代码质量所消耗的推理 token。该维度不能脱离完成度和产物质量单独解释。

关注内容包括：

- 总 inference token；
- 每个有效通过项的 token 成本；
- 每个完整任务的 token 成本；
- 读取、分析、实现、测试和修复各阶段的 token 分布；
- 是否存在重复读取、无效探索或过度分析；
- 是否发生大量重试和返工；
- 低 token 是否以遗漏任务或降低质量为代价；
- 高 token 是否产生了可验证的质量、泛化或性能收益。

## 使用原则

- 八个维度互相独立展示，不生成综合总分。
- 不引用严格榜或宽松榜名次作为维度证据。
- 每个模型可以采用不同的证据抽取细节，但所有结论必须回溯到 solution、正式评分 JSON、audit 或 events。
- 同一行为可以作为多个维度的背景证据，但必须解释它分别影响哪个能力，不得无说明重复扣分。
- 证据不足时标记“待验证”，不能为了减少并列而主观补分。
- 后续维度排名应来自逐模型评价结果，而不是由现有总榜倒推。
